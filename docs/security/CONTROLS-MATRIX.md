# HVE-Forge Security Controls Matrix

`Current` means enforced by the active fixture runtime. `Planned` means required before the named capability can be enabled and must not be cited as release evidence yet.

| Threat or requirement | Preventive control | Detective control | Evidence |
|---|---|---|---|
| Goal hijacking | Current: every model-bound byte carries an origin/trust envelope (`core/trust.ts`) and cannot alter policy, approval, or registration; live retrieval remains fixture/recorded-provider only | Trust-envelope and context-assembly injection tests | `tests/core/trust.test.ts`, `tests/application/context-assembler.test.ts` |
| Tool misuse | Current: every registered tool (read/list/search/replace) crosses the capability-classed registry, schema validation, and deny-by-default dispatcher before any effect | Policy, admission, and denied-side-effect tests | `tests/core/tool-registry.test.ts`, `tests/application/tool-dispatcher.test.ts` |
| Identity abuse | No ambient credentials; agent identity cannot approve | Approval identity tests | Approval gate suite |
| Supply-chain compromise | Pinned dependencies/actions, lock files, hashes | Dependency audit, CodeQL, SBOM | Lock files, CI, SBOM |
| Unexpected code execution | No process/shell capability in v0.2; execute-class tools require a registered isolation backend, which is absent; package lifecycle scripts disabled | Architecture and package checks | Boundary test, package allowlist, `.npmrc` |
| Memory poisoning | Provenance, trust, scope, confidence, expiry, deletion | Memory validation/dedup tests | Memory schema and suite |
| Insecure inter-agent messages | Agent message is never human approval | Approval negative tests | Approval gate suite |
| Cascading failure | Hard decisions, dispatches, provider ceilings, stage time, token, and cost limits; the bounded agent loop adds turn/dispatch/token budgets, oscillation detection, and a three-strikes failed-fix rule | Limit, handoff-budget, and loop-termination tests | Projection/events/handoff budget suite; `tests/application/agent-loop.test.ts` |
| Human trust exploitation | Current: fixture hash binding, read-only evaluation, and a named `FRESH`/`STALE`/`MISSING` working-tree freshness grade for schema-v2 sessions; schema-v1 completion remains hash-bound only by design (frozen replay) | False-completion, stale-tree, and freshness-grade tests | `tests/core/session-completion.test.ts`, `tests/adapters/working-tree-fingerprint.test.ts` |
| Rogue loops | Schema v1: single-decision workflow and hard budgets. Schema v2: bounded multi-turn loop terminates on exactly one of six typed reasons (provider completion, decision budget, wall clock, oscillation, failed-fix exhaustion, cancellation); no path permits unbounded iteration | Decision/dispatch limit tests; loop-termination tests for every reason | Guard suite; `tests/core/sessions.test.ts`, `tests/application/agent-loop.test.ts` |
| Path escape | Relative path, containment, device/ADS/trailing-name rejection, link checks immediately before mutation; the working-tree fingerprinter applies the same link rejection | Hostile path and link tests | Adapter suite; `tests/adapters/working-tree-fingerprint.test.ts` |
| Secret disclosure | Classified references and redaction before sinks | Canary scan across stdout/stderr/state | E2E redaction test |
| Audit forgery | Current SHA-256 chain (both schema v1 and v2) detects corruption and partial tampering; planned CI signature supplies authenticity | Metadata/event/artifact/archive tamper tests | Replay suite (both schema families); trusted attestation pending |
| Stale completion | Current: schema-v1 fixture workspace/projection/event/evaluator hash binding; schema-v2 completion additionally grades a tracked-and-untracked-inclusive working-tree fingerprint as `FRESH`/`STALE`/`MISSING` and accepts `FRESH` only | Stale, post-mutation, and freshness-grade tests | `tests/core/session-completion.test.ts` |
| Denial of wallet | No live provider except the VS Code Copilot vertical slice, which is host-managed cost with no invented monetary value; cost limit defaults to zero elsewhere | Usage/cost metrics when enabled | Run descriptor and telemetry |
| Protocol confusion | MCP version/capability metadata and explicit extensions | Dated conformance fixtures | MCP matrix and tests |
| Host configuration drift | One canonical catalog, generated provenance, manifest ownership, duplicate scan checks | `render --check` and `doctor` | Structural renderer evidence; VS Code/Cursor/Claude remain kernel-mediated, Cowork and generic remain declarative |
| Hook trust | Executable host hooks disabled by default and never treated as the policy root | Enforcement-tier diagnostics | Host profiles and `doctor` report |
| Node dependency compromise | Zero production dependencies, exact development pins, disabled scripts, locked install | npm audit, package allowlist, CodeQL, SBOM | `npm run quality` and SHA-pinned CI |
| Distribution-root confusion | Current: module-relative package authority is separate from target workspace input; a `--repository-root` override that disagrees with the installed root is rejected | Packed poison-target consumer test | `tests/cli/distribution-root.test.ts`; `npm run test:packed-consumer` |
| Native host-tool bypass | Current: default generated agents have no native privileged tools; the VS Code extension contributes zero globally invokable language-model tools, and workspace-content/mutation tools stay private to the HVE-owned loop | Host security-readiness scan; manifest tool-contribution validation | `tests/hosts/security-readiness.test.ts`, `tests/extension/tool-contribution.test.ts` |
| Provider data egress | Current: the bounded loop is the only path that can invoke a model or dispatch a tool, both policy-gated. Planned: a durable pre-send egress receipt before every live provider call (SPEC-004 section 3.6), including the VS Code Copilot channel, is not yet implemented | Fake provider proves zero calls when the model is unavailable | `tests/extension/language-model-port.test.ts`; egress receipts remain an open gap for any live provider |
| Cowork package tampering | Current: strict manifest schema validation, exact icon-dimension checks, deny-by-default skill eligibility (`cowork-eligible: true` required), no wrapper directory | Manifest and package-content tests | `tests/adapters/cowork-package.test.ts`, `tests/cli/cowork-package.test.ts` |
| Untracked or unverifiable release candidate | Current: `check:tracked-input` fails closed on any uncommitted or untracked path; `release:digests` records a SHA-256 manifest over the packed tarball, Cowork package, and SBOM | Tracked-input gate; digest manifest inspection | `scripts/check-tracked-input.mjs`, `scripts/write-artifact-digests.mjs`, `artifacts/digests.json` |
